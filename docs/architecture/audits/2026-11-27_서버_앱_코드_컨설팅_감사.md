## 잘된 점
- 앱 규칙 테스트(`mobile/tests/architecture/architecture-rules.test.ts`)가 계층·토큰·움직임·외부 통신·브랜드 색을 이미 강제, 예외 목록이 비어 있음.
- 서버 `AiApiKeyCallRunner`·`ProviderHttpClient` 가 키 순회·HTTP 공통 경로 한 곳, 제공자 클래스엔 제공자 고유 코드만.
- 처리 서비스가 "제공자 장애(틱 멈춤)"와 "건별 실패(기록)"를 구분 (`SummaryStep.PROVIDER_FAILED`, `ImageOutcome.STORAGE_FAILED`).
- `ConfigKey` 설정 단일 원본, `Clock` 주입, 비밀값은 로그에 키 ID만.
- 300줄 넘는 파일 0, 약어·is 없는 boolean 거의 없음.

## 확인하지 못한 것
- 앱 화면은 띄워 보지 않음 (이번 정리는 표시 결과가 같은 구조 변경, 단위 테스트로만 확인).
- `ConfigKey` 기본값 ↔ `application.yml` 값 어긋남 여부.
- `@Value` 기본값을 지워도 되는지 (테스트가 항상 `application.yml` 을 읽는지).
