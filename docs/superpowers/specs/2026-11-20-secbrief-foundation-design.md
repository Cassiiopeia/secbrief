# 시큐브리프 기본 설계 (2026-11-20)

상태: 초안. 사용자가 대화에서 정한 것과 작성자가 제안한 것을 구분해 적는다.
`[결정]`은 사용자가 정한 것, `[제안]`은 작성자 판단이라 바꿀 수 있는 것, `[미확인]`은 아직 확인하지 못한 것이다.

## 1. 무엇을, 왜

국내에서 서비스를 운영하거나 정보보호·개인정보보호에 관심 있는 사람이 **봐야 할 보안 소식을 한 앱에서 한국어로 따라가게** 한다.

- `[결정]` 다루는 것: 긴급 보안 소식, 최신 뉴스, 전 세계 동향, 주간 트렌드, 내 스택에 해당하는 취약점 공지
- `[결정]` 전달: 앱과 푸시 알림. 웹·메일은 하지 않는다
- `[결정]` 스토어에 올린다. 먼저 Android 비공개 테스트에 올리고 14일 동안 빠르게 개발한다
- `[결정]` 사용자 수는 적을 것으로 본다. 만드는 사람의 본업 도메인이라 직접 쓰는 도구이자 이력으로 만든다
- 지금은 KISA, 개인정보위, 언론, 해외 원문을 각각 따로 봐야 한다. 국내에 이를 모은 앱은 조사에서 찾지 못했다

### 목표

1. 아침에 3분 안에 오늘 볼 것을 다 본다
2. 긴급한 것은 놓치지 않는다 (푸시)
3. 취약점 공지는 "개요 / 영향받는 버전 / 조치 방안 / 참고" 형식으로 읽는다
4. 매일 다시 열 이유가 있다 (오늘 브리핑 진행도, 연속 확인 일수, 조치 상태 표시)

### 하지 않는 것

- 웹 서비스, 메일 뉴스레터
- 팀 기능(사내 메신저 연동, 공지 초안 공유), 유료 구독, 광고: 첫 출시 뒤로 미룬다
- 사용자 서버를 직접 점검하는 기능(스캐너)
- 기사 본문 전재, 언론사 대표 이미지 사용

### 이렇게 되면 실패

- 영향 버전·조치 버전 숫자가 원문과 다르다
- 긴급 푸시가 하루에도 여러 번 와서 알림을 끈다
- 요약만 있고 원문 링크가 없어 확인할 수 없다

## 2. 검토한 방법

| 안 | 내용 | 결과 |
|---|---|---|
| 웹 + 메일 먼저 | 수집·정리 서버, 공개 웹, 주간 메일 | 가장 빠르지만 사용자가 원하지 않음 |
| **앱 먼저** | React Native(Expo) 앱 + Spring 서버 + 푸시 | `[결정]` 선택. passQL 구조를 본보기로 삼음 |
| 내 채널 알림 먼저 | 수집 결과를 개인 메신저 채널로만 보냄 | 남에게 보여 줄 결과물이 없어 제외 |

앱 기술은 처음에 Flutter로 틀과 홈 화면을 만들었다가 React Native(Expo)로 바꿨다 `[결정]`. 사용자가 써 보지 않은 기술을 써 보려는 목적이고, 가장 널리 쓰이는 표준 구성(Expo, TypeScript, Expo Router, Reanimated, TanStack Query)으로 간다. 유료 클라우드 빌드(EAS)는 쓰지 않고 GitHub Actions에서 직접 빌드한다.

## 3. 구조

모노레포 하나에 앱과 서버를 둔다 `[결정]`.

```
secbrief/
├── mobile/   React Native(Expo) 앱 (Android, iOS)
├── server/   Spring Boot 멀티모듈 (수집·정리·알림·API)
├── brand/    브랜드 색·아이콘 단일 원본
└── docs/     설계 문서
```

앱은 서버하고만 통신한다. 외부 출처와 AI 제공자는 서버만 부른다.

하단 탭 5개 `[제안]`.

| 탭 | 내용 |
|---|---|
| 오늘 | 긴급 소식, 이번 주 1위 주제, 연속 확인 일수, 시간순 스트림 |
| 뉴스 | 국내외 보안 소식 목록. 국내/해외, 주제로 걸러 봄 |
| 동향 | 주간 정리. 많이 나온 주제·공격 유형·제품 순위와 지난주 대비 증감 |
| 취약점 | 내 스택 공지와 전체 공지. 심각도·제품으로 걸러 봄. 공지별 조치 상태(확인함, 조치 예정, 조치 완료) |

그 밖의 화면: 공지 상세, 뉴스 상세(요약 + 원문 링크), 첫 실행 안내(제품·주제 고르기, 알림 허용).

### 디자인

`[결정]` "스트림" 방향. 색 블록 타일, 시간이 붙은 타임라인, 대문자 고정폭 라벨이 특징이다.

- 색: 바탕 `#131313`(다크)·`#f4f4f0`(라이트), 민트 `#3cffd0`, 보라 `#5200ff`
- 글꼴: Pretendard, 고정폭은 D2Coding
- 이미지 `[제안]`: 긴급 소식이 있으면 큰 커버, 없으면 목록 썸네일만. 그림은 주제별 자체 그림 세트를 쓴다
- 애니메이션: 순차 등장, 숫자 세어 올리기, 긴급 표시 맥박, 누름 축소. 기기의 동작 줄이기 설정을 따른다
- 색 조합은 The Verge 공개 규격에서 가져온 값이라, 출시 전에 고유 조합으로 조정한다 `[제안]`

시안과 결정 기록: `docs/projectops/ui-design/20261120_001_테마_시안_3종/`

## 5. 수집 대상

`[제안]` 첫 출시 범위. 각 출처의 RSS·API 제공 여부는 구현 첫날 확인한다 `[미확인]`.

| 구분 | 출처 | 쓰임 |
|---|---|---|
| 국내 기관 | KISA 보호나라·KNVD 보안공지 | 취약점 공지, 긴급 판정 |
| 국내 기관 | 개인정보보호위원회 보도자료 | 유출 사고, 처분, 법 개정 |
| 국내 기관 | 금융보안원, 국가사이버안보센터 | 권고문 |
| 해외 원천 | NVD | CVE 점수, 영향 제품 |
| 해외 원천 | 미국 CISA 악용 확인 목록(KEV) | 긴급 판정 |
| 제품 공식 | PostgreSQL, Apache(Tomcat·HTTPD), nginx, OpenSSH, PHP, OpenJDK 등 | 영향 버전·조치 버전의 근거 |
| 매체 | 국내외 보안 매체 | 뉴스. 제목 + 링크 + 자체 요약만 |

## 6. 서버 처리 흐름

```
주기 수집 → 중복 제거 → 분류 → AI 정리 → 검증 → 긴급 판정 → 저장 → 푸시
```

1. **수집**: 출처마다 수집기 하나. 정해진 주기로 새 글만 가져온다
2. **중복 제거**: 같은 CVE·같은 사건을 다룬 글을 하나로 묶는다
3. **분류**: 종류(공지, 뉴스), 주제 꼬리표, 관련 제품, 심각도
4. **AI 정리**: 공지는 개요·영향 버전 표·조치 방안·참고로, 뉴스는 한국어 한 줄 요약으로 만든다
5. **검증**: AI가 낸 버전 숫자가 원문에 글자 그대로 있는지 대조한다. 없으면 그 칸을 "원문에 없음"으로 바꾼다
6. **긴급 판정**: CVSS 9.0 이상, 악용 확인 목록 등재, KISA 긴급 공지 중 하나에 해당하면 긴급
7. **푸시**: 긴급은 해당 제품·주제 구독자에게 바로 보내고, 나머지는 아침 브리핑 한 번에 모은다

### 실패 경로

| 상황 | 동작 |
|---|---|
| 출처 수집 실패 | 그 출처만 건너뛰고 기록. 연속 실패 시 관리자에게 알림 |
| AI 호출 실패 | 원문 제목과 링크만으로 먼저 올리고, 나중에 다시 정리 |
| 검증에서 숫자 불일치 | 그 숫자를 싣지 않고 원문 링크로 안내 |
| 앱에서 서버 응답 없음 | 마지막으로 받은 내용을 보여 주고 재시도 버튼과 에러 코드 표시 |
| 푸시 권한 거부 | 앱은 그대로 동작. 설정에서 다시 켤 수 있다고 안내 |

## 7. 데이터 구조 초안

| 묶음 | 테이블 | 내용 |
|---|---|---|
| 수집 | `source`, `collected_item` | 출처, 가져온 원문 기록 |
| 소식 | `article` | 뉴스 제목, 요약, 원문 링크, 출처, 국내/해외 |
| 공지 | `advisory`, `advisory_affected_version`, `advisory_reference` | CVE, 점수, 개요, 영향·조치 버전, 참고 링크 |
| 분류 | `product`, `topic`, 연결 테이블 | 제품, 주제 꼬리표 |
| 사용자 | `member`, `member_product`, `member_topic` | 기기 단위 계정, 구독 |
| 알림 | `push_token`, `notification_preference`, `push_send_history` | 푸시 |
| 재방문 | `member_read_state`, `member_advisory_action` | 읽음, 조치 상태 |
| 동향 | `weekly_trend` | 주제별 주간 건수와 증감 |

로그인은 첫 출시에서 넣지 않고 기기 단위 익명 계정으로 시작한다 `[제안]`. 계정 연동은 기기 변경 요구가 생기면 넣는다.

## 9. 테스트

- 버전 숫자 검증기: 원문에 없는 숫자가 걸러지는지 (가장 큰 사고를 막는 곳)
- 긴급 판정 규칙: 경계값(CVSS 8.9와 9.0)
- 수집기: 저장해 둔 실제 응답 표본으로 해석이 되는지
- 앱: 타입 검사, 린트, 규칙 테스트, 실기기 확인

## 10. 아직 정해지지 않은 것

- 앱 이름과 패키지 ID 확정. 지금은 `시큐브리프`, `kr.suhsaechan.secbrief`. Play에 올리면 못 바꾼다
- GitHub 레포를 어느 계정·조직에 만들지
- 서버를 어디에 띄울지
- AI 제공자와 모델, 월 비용 한도
- Play 비공개 테스트 요건(테스터 12명, 14일)이 이 개발자 계정에 적용되는지 `[미확인]`
- 재직 중인 회사의 겸업·이해충돌 규정 `[미확인]`
