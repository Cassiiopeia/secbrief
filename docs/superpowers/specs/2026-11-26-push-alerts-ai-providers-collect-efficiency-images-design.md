# 긴급 알림, AI 제공자·요약, 수집 확장, 이미지, 검색, 화면 재구성 설계 (#33)

작성일 2026-11-26. 사용자가 "묻지 말고 전부 구현"을 지시해 승인 절차 없이 결정했고, 결정과 이유를 여기에 남긴다.

## 1. 목표

| 영역 | 지금 | 바꾼 뒤 |
|---|---|---|
| 알림 | 없음 (앱을 열어야 긴급 소식을 앎) | 종류별로 켜는 푸시 알림, 새 긴급 소식을 묶어 1건 |
| AI | Anthropic 고정, 기사 1건당 호출 1번, 운영 키 없음(번역 0건) | 설정으로 Anthropic·Ollama 선택, 여러 건을 호출 1번에 |
| 수집 | 매번 피드 전체 내려받기, 기사마다 중복 조회, 출처 차례 수집 | 조건부 요청(304), 중복 묶음 조회, 출처 동시 수집 |
| 이미지 | 없음 | 피드가 준 대표 이미지를 줄여서 MinIO 에 저장, 서버 API 로 제공 |

## 2. 알림

- **종류 3개** (`AlertCategory`): `KISA_URGENT`, `KEV`, `CRITICAL_CVE`. 기사 1건은 종류 1개 (KEV 등재 > KISA 공지 > 그 밖).
- **기기 등록** `PUT /api/v1/push-devices` `{pushToken, platform, enabledAlertCategories}`. 회원이 없어 푸시 토큰이 기기 식별값. 빈 목록이면 기기를 지운다.
- **발송**: 5분 틱. 긴급이고 `urgent_notified_at` 이 비어 있는 기사를 모아, 기기마다 켠 종류에 맞는 기사만 묶어 1건을 보낸다 (기사마다 보내지 않는다: NVD 고위험 건수가 많아 알림이 쏟아지는 것을 막음).
- **번역 대기**: AI 처리가 끝났거나 수집 후 10분이 지난 기사만 알린다 (한국어 제목으로 알리려고).
- **다시 알림**: 고위험으로 이미 알린 취약점이 KEV 에 오르면 다시 알린다 (`markKev` 가 발송 표시를 비움).
- **실패 처리**: 발송이 전부 실패하면 기사를 대기로 남겨 다음 틱에 다시. 받을 기기가 없으면 처리한 것으로 표시 (나중에 등록한 기기에 지난 소식을 몰아 보내지 않음).
- **무효 토큰**: 발송 응답과 15분 뒤 접수증에서 `DeviceNotRegistered` 면 기기를 지운다.
- **제공자**: `PushSender` 규약 + Expo 구현체. Expo 를 고른 이유: 서버가 FCM·APNs 인증서를 직접 다루지 않고 API 하나로 두 플랫폼에 보낸다. 다른 Expo 프로젝트의 토큰이 등록돼 요청이 통째로 거부되면 그 토큰을 가려내 지우고 나머지를 다시 보낸다.
- **마이그레이션**: 기능 이전에 쌓인 긴급 기사는 발송 표시를 채워 알리지 않는다.
- **앱**: 설정 탭 알림 구역(종류별 스위치), 채널 `urgent-alerts`, 알림을 누르면 `data.targetTab` 탭으로 이동.

## 3. AI

- `secbrief.ai.provider` (`anthropic` | `ollama`) 로 구현체 선택. 프롬프트·JSON 스키마·응답 해석·번역 검증은 제공자와 무관한 공통 코드.
- 묶음 분석: 제목 여러 건을 번호와 함께 한 번에 보내고 번호별 결과를 받는다. 빠진 번호·중복 번호·모르는 주제는 그 건만 실패.
- 번역 검증(원문에 없는 숫자열이면 폐기)은 건별로 유지 (서비스 원칙 2).

## 4. 수집

- 조건부 요청: RSS·KEV 는 `ETag`/`Last-Modified` 를 저장해 다음 요청에 보낸다. 304 는 성공으로 기록. 검증값은 저장까지 끝난 뒤에만 기록 (중간 실패 시 누락 방지).
- 중복 묶음 조회: CVE 없는 초안의 링크를 한 번의 IN 조회로 거른다.
- 동시 수집: 출처마다 가상 스레드. 같은 CVE 를 두 출처가 동시에 저장할 때는 행 잠금과 재시도로 병합을 지킨다.
- `Article` 은 바뀐 열만 UPDATE (`@DynamicUpdate`): 수집 병합·AI 기록·알림 표시·이미지 기록이 서로의 열을 덮지 않게.

## 5. 이미지

- 피드가 준 대표 이미지 주소만 쓴다 (enclosure, Media RSS, 요약의 첫 이미지). 기사 페이지를 긁지 않고 본문은 저장하지 않는다.
- 내려받기는 외부 입력 주소라 사설·루프백 주소 차단, 리다이렉트 제한, 크기·형식 제한을 둔다.
- 긴 변 800px JPEG 로 다시 인코딩해 MinIO 에 저장하고, 앱에는 `GET /api/v1/articles/{id}/image` 로 제공한다 (앱은 server 하고만 통신).
- 저장소 설정이 없으면 이미지 처리만 건너뛴다.

## 5-1. 큰 소식 위주 (중요도)

- AI 가 제목으로 중요도 3단계를 매긴다: `HEADLINE`(널리 쓰는 제품의 악용·대규모 사고·국가 경보), `NOTABLE`, `ROUTINE`.
- 규칙 하한: KISA 경보단계 상향은 HEADLINE, KEV 등재·KISA 긴급 공지는 NOTABLE 이상. AI 가 없거나 실패해도 큰 소식이 묻히지 않는다.
- 오늘 화면 `headlineItems`(72시간, 중요도 높은 순 6건), 목록 필터 `minimumImportance`·`sourceCode`.
- 고위험 CVE 알림은 AI 가 ROUTINE 으로 본 것을 보내지 않는다 (AI 판단이 없으면 보낸다).
- 제목 속 회사·제품 이름(`subjectName`)은 제목에 그대로 있는 글자만 받는다.

## 5-2. 출처 확장

| 묶음 | 출처 코드 |
|---|---|
| KISA 보호나라 | `KISA`(보안공지), `KISA_VULNERABILITY`, `KISA_REPORT`, `KISA_ALERT_LEVEL` |
| 리눅스 배포판 | `UBUNTU_USN`, `DEBIAN_DSA`, `REDHAT_RHSA` |
| 오픈소스·런타임 | `GHSA`(critical), `GHSA_HIGH`, `NODEJS_SECURITY` |

- 모두 공식 공개 피드이고 2026-11-26 에 실제로 열리는지 확인했다. KISA 공지사항 피드(사이트 점검 안내)와 MSRC 피드(3MB, 건수 과다)는 넣지 않았다.

## 5-3. 앱 안 상세와 AI 요약

- 기사를 누르면 브라우저가 아니라 앱 안 상세를 연다. 원문 보기 버튼은 항상 둔다.
- 요약 입력은 출처가 직접 준 글만 쓴다: RSS 항목 요약문, NVD·KEV·GHSA 공개 설명. 기사 페이지를 긁지 않는다. 입력은 요약이 끝나면 지운다.
- AI(Claude Haiku 5.5)가 요약 3~5문장, 핵심 2~4개, 대응 안내(입력에 적힌 조치만)를 쓴다. 입력에 없는 숫자가 나오면 버린다.
- 영향 버전·조치 버전·조치 기한은 AI 를 거치지 않고 원문 데이터 값 그대로 보여 준다 (`facts`).
- 상세 아래에 관련 기사 6건 (같은 CVE > 같은 회사·제품 > 겹치는 키워드 > 같은 주제).

## 5-4. 키워드, 검색, 행사

- AI 가 제목에서 키워드를 최대 5개 뽑는다. 키워드별 목록, 주간 키워드 순위(앞 기간 대비 순위 변화).
- 검색: 글자 일치 검색이 기본이고, 임베딩 제공자(Ollama)가 설정되면 의미 검색. 공용 DB 에 확장을 설치하지 않으려고 벡터는 `real[]` 로 두고 서버가 계산한다.
- 행사 소식: 주제 `EVENT` 를 추가해 수집한 기사 중 행사 소식을 날짜순으로 보여 준다. 행사 일정 자체를 따로 수집하지는 않는다.

## 5-5. 하단 내비게이션

| 탭 | 역할 |
|---|---|
| 홈 | 오늘의 브리핑: 주요 소식, 긴급, KISA 경보 상태, 숫자, 주제·키워드 바로가기 |
| 소식 | 뉴스·공지 피드와 카테고리 칩 |
| 취약점 | 주요만 / 악용 중 / 전체, 출처 묶음(KISA, 오픈소스, 리눅스, 런타임) |
| 탐색 | 검색, 키워드 순위, 주제 동향, 행사 소식 |
| 더보기 | 알림 설정, 출처, 문의, 약관, 앱 정보 |

## 6. 하지 않는 것

- 회원·로그인, 알림 금지 시간대, 기사별 개별 알림, 제품별 구독.
- KISA 공지 페이지 본문 수집(피드에 요약문이 없어 KISA 항목은 AI 요약이 없다), 행사 일정 달력.
- 푸시 인증 설정(Expo 프로젝트, FCM, APNs), MinIO 접속 정보, AI 키 등록: 사용자 계정이 필요해 구현 범위 밖.
- 스토어 배포와 Play 데이터 보안 선언 변경: 사용자가 명시적으로 요청할 때 진행.

## 7. 배포 전에 맞춰야 하는 것

- 개인정보처리방침·약관에 푸시 토큰 처리 문구를 넣었다 (`site/`). `main` 에 합쳐지면 바로 공개된다.
- Play Console 데이터 보안 선언("수집 안 함")과 스토어 설명을 알림 기능에 맞게 바꿔야 한다 (#26 심사 대기 중).
