# 알림함 · 공지사항 · 방해 금지 시간 설계 (#70)

- 이슈: https://github.com/Cassiiopeia/secbrief/issues/70
- 상태: 승인된 설계 + 구현하며 다듬은 점 (이 문서 끝 「구현하며 다듬은 점」)

## 문제

1. 묶음 알림(기사 2건 이상)은 `targetTab` 만 실어서, 눌러도 탭만 열려요. 무엇을 알렸는지 다시 볼 곳이 없어요.
2. 보낸 알림을 저장하지 않아요 (`article.urgent_notified_at` 만 남음). 서비스 공지라는 개념도 없어요.
3. 수집 주기(약 2시간)마다 시간과 상관없이 보내서 밤에도 알림이 와요.

## 결정

### 1. 알림함 기록 (서버)

- 표 `notification` 하나에 종류 두 가지를 둬요.
  - `ALERT`: 긴급 알림 발송 기록. 대표 알림 종류, 제목, 본문, 만든 시각, 푸시 처음 보낸 시각(모두 보류 중이면 null), 묶인 기사(`notification_article`: 순서, 기사 번호, 기사별 알림 종류).
  - `NOTICE`: 관리자가 쓴 공지. 제목, 본문(글자만, 줄바꿈 그대로), 선택 링크(http·https), 고정 여부, 만든·고친 시각.
- 긴급 알림 틱마다 알릴 기사 **전체**를 기록 1건으로 남겨요. 기기가 없어도 남겨요 (알림함은 모든 사용자가 같은 내용을 봐요).
- 기기마다 켠 종류가 달라 푸시 글은 기기마다 다를 수 있어요. 모든 기기의 푸시가 같은 기록 번호를 가리키고, 상세는 종류별로 묶어 보여 줘요 (그 기기가 켜지 않은 종류도 보일 수 있음).
- 보관: `ALERT` 30일 (6시간마다 정리), `NOTICE` 는 관리자가 지울 때까지.
- 발송이 전부 실패한 틱은 기록을 지우고 기사를 대기로 남겨요 (다음 틱에 새 기록, 두 번 쌓이지 않게).
- 마이그레이션: `V0.8.1__add_notification_inbox_and_quiet_hours.sql` (#67 의 `V0.8.0` 과 겹치지 않게, 그 파일에 기대지 않음).

### 2. 푸시 data

| 키 | 값 | 언제 |
|---|---|---|
| `notificationId` | 알림함 번호 | ALERT · NOTICE |
| `notificationKind` | `ALERT` · `NOTICE` · `QUIET_HOURS_DIGEST` | 항상 |
| `articleId` | 기사 번호 | 기사 1건 알림만 |
| `targetTab` | `vulnerability` (긴급·모음) · `today` (공지) | 항상 (이전 앱용) |

키 원본은 서버 `NotificationPushData`, 앱은 `toNotificationTargetRoute` 가 읽어요.

### 3. 알림을 눌렀을 때 (앱)

순서대로: 기사 1건 → 기사 상세, 공지 → 공지 상세, 그 밖의 알림함 번호 → 알림 상세, 모음 알림 → 알림함, 이전 data → 지금처럼 탭. 꺼진 앱에서 누른 경우도 화면 스택이 준비된 뒤 이동해요.

### 4. 알림함 화면 (앱)

- 오늘 탭 머리의 종 아이콘 + 새 알림 점 → `/notifications` (알림 | 공지사항).
- 알림: 날짜별 묶음(오늘, 어제, 날짜), 행마다 종류 배지 · 제목 · 대표 기사 제목 · "외 N건" · 상대 시각, 안 읽은 행 강조.
- 공지사항: 고정 먼저, 제목 · 날짜 · 안 읽음 표시.
- 읽음은 기기에만 저장해요 (회원 없음). 서버 `GET /api/v1/notifications/latest` 의 종류별 최근 번호와 기기에 저장한 본 번호를 비교해 점을 정해요.

### 5. 알림 상세 · 6. 공지 상세

- 알림 상세: 무엇을 왜 알렸는지(종류 설명), 시각, 종류별 기사 목록(기존 기사 행 재사용, 누르면 기사 상세).
- #71 "대응 모아보기"는 알림 상세의 종류별 묶음 뒤에 붙일 수 있게 구조만 나눠 둬요 (자리 표시 화면은 없음).
- 공지 상세: 제목, 날짜, 본문, 링크가 있으면 바로 가기 버튼.

### 7. 방해 금지 시간

- 기기별로 서버(`push_device`)에 저장: 켜짐, 시작, 끝, 시간대(기기 시간대, 기본 Asia/Seoul).
- **기본값: 기존·새 기기 모두 꺼짐.** 켤 때 앱이 22:00~08:00 을 채워 줘요. 사용자가 켜지 않은 보류는 하지 않는 편이 가장 덜 놀라워요 (알림이 갑자기 안 오는 일이 없음).
- 구간은 기기 시간대 기준 `[시작, 끝)`. 끝이 시작보다 이르면 자정을 넘겨요 (22:00~08:00).
- 시작 == 끝: 켤 때는 `QUIET_HOURS_SAME_TIME` 으로 거부하고 앱도 저장 전에 막아요. 꺼져 있으면 그대로 저장해요 (쓰지 않음). 계산에서는 빈 구간이에요.
- 모르는 시간대는 `INVALID_TIME_ZONE`.
- 방해 금지 시간에는 그 기기가 받을 글을 그대로 보류해요 (KEV 도 예외 없음). 알림함 기록은 바로 보여요.
- 끝난 뒤 첫 알림 틱(5분 주기)에 보류분이 1건이면 그 글 그대로, 여러 건이면 모음 1건을 보내요. 실패하면 보류분을 남겨 다음 틱에 다시 보내요.
  - 모음 제목: "방해 금지 시간에 긴급 소식 N건이 들어왔어요" (N 은 기사 수), 공지만이면 "방해 금지 시간에 공지사항 M건이 올라왔어요", 둘 다면 "방해 금지 시간에 긴급 소식 N건, 공지사항 M건이 있었어요". 본문 "알림함에서 한 번에 모아 볼 수 있어요".
- API: 기존 `PUT /api/v1/push-devices` 요청에 `quietHours` 를 선택으로 더해요. 없으면(이전 앱) 저장값을 그대로 둬요. 응답에는 항상 `quietHours` 가 있어요.
- 알림 종류를 모두 끄면 서버가 기기 행을 지우므로 방해 금지 시간도 함께 사라져요. 앱은 켠 종류가 없으면 방해 금지 행을 잠가요.

### 8. 관리자

- `/admin/notices`: 새 공지 쓰기(제목 1~100자, 본문 1~5000자, 선택 링크, 고정, "푸시도 보내기"), 표(고정 먼저), 고치기, 고정·풀기, 지우기(확인 창). 바꾼 내용은 관리자 기록에 남아요.
- "푸시도 보내기"를 고르면 확인 창이 받을 기기 수를 알려 줘요. 알림을 켠 기기 전체에 보내고, 방해 금지 기기는 보류해요. 고칠 때는 다시 보내지 않아요.
- `/admin/alerts`: 최근 30일 긴급 알림 기록 (앱 알림함과 같은 조회).

### 9. API

| API | 설명 |
|---|---|
| `GET /api/v1/notifications?kind=ALERT\|NOTICE&cursor=&size=` | 목록 `{items, nextCursor}`, 크기 기본 20 · 최대 50 |
| `GET /api/v1/notifications/latest` | `{latestAlertId, latestNoticeId}` (이용 집계에서 뺌) |
| `GET /api/v1/notifications/{id}` | 상세, 없거나 지운 기록은 404 `RESOURCE_NOT_FOUND` |

공개 조회라 인증이 없어요 (기사와 같음). 커서는 (고정 여부, 만든 시각 밀리초, 번호) 를 URL-safe Base64 로 담아요.

## 구현하며 다듬은 점

- 서버 기록 1건 = 틱 1회 (기기마다 따로 만들지 않음). 이유: 알림함은 전 사용자 공용이고, 기기별 기록은 같은 소식을 여러 줄로 보여 줘요.
- 목록 응답에 `alertCategories`(묶인 종류 전체)와 `leadArticleTitle`(지금의 한국어 제목)을 더했어요. AI 번역이 알림 뒤에 끝나도 알림함에는 한국어 제목이 보여요.
- `GET /api/v1/notifications/latest` 는 앱을 열 때마다 불려 화면 이용 집계에서 뺐어요.
- 공지 푸시도 방해 금지 시간을 따르고, 모음 제목은 긴급 소식·공지를 나눠 세요.
- 관리자 확인 창: 체크 상자에 `data-confirm-message-when-checked` 를 두면 그 문구로 바뀌어요 (푸시도 보내기를 고르면 받을 기기 수를 보여 줌).
- 앱: 종 아이콘은 오늘 탭뿐 아니라 탭 머리 네 곳(홈, 소식, 취약점, 더보기)에 같은 자리로 둬요. 더보기 > 알림에도 "알림함" 행을 둬요.
- 앱: 공지사항 행은 배지가 없어 날짜를 제목 아래로 내렸어요. 보관 기간이 지난 알림은 "보관 기간이 지난 알림이에요" 화면과 알림함 바로 가기를 보여 줘요.
- 앱: 꺼진 앱에서 누른 알림은 루트 내비게이터가 준비된 뒤(`useIsRootNavigatorReady`) 한 번만 이동해요. SDK 58 의 `useRootNavigationState` 는 준비 전 상태에서 예외를 던져 쓰지 않았어요.
- 앱: 시간 고르기는 이미 쓰는 `@expo/ui/community/datetime-picker` (SDK 58 의 `@react-native-community/datetimepicker` 대체)로 해요. 웹은 시각 글자만 보여 줘요.
- 앱: 기기 저장 키 `secbrief.notificationReadState`(종류별 본 번호, 연 번호 최대 500개), `secbrief.quietHours`.
- 관리자: 알림 기록 화면은 조각 인자 안에서 빈 호출이 막혀(Thymeleaf 제한) 종류 이름·색을 `th:with` 로 먼저 계산해요.

## #71 (대응 모아보기) 연결 지점

- 앱 `features/notifications/notification-detail-view.ts` 의 `AlertDetailBlock` 은 종류 `'categoryArticles'` 하나인 합 타입이에요. 새 종류를 더하고 `alert-detail-content.tsx` 의 `AlertDetailBlockView` 에 경우를 하나 더하면 돼요.
- 서버 상세 응답 `NotificationDetailResponse.articleSections` 는 종류별 기사 묶음이에요. 묶음이나 상세에 대응 요약을 붙일 때는 이 응답에 필드를 더해요 (`ArticleResponse` 는 #67 과 겹치니 건드리지 않음).
- 종류 설명 글은 앱 `alert-category-texts.ts` 한 곳에만 있어요.
